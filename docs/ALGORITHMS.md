# Implemented Algorithms

This document describes the current implementation in `backend/include/simulation.hpp` and the API in `backend/src/main.cpp`.

## Simulation clock and concurrency

Simulation time is an integer number of minutes. `tick()` advances the clock once and performs due-flight admission, fuel consumption and escalation, runway service/clearance, dispatch, and queue-statistic sampling. The background thread only calls this same tick function at the selected real-time interval. Manual step requests also call it directly.

The engine protects mutable state with one mutex. API handlers take that lock through the public simulation methods, so state reads and writes are serialized with background ticks and with each other. There is one `active_` flight index. `activeFlights` counts flights in `Landing` or `TakingOff`, and cannot exceed one. `runway_` is `FREE`, `OCCUPIED_LANDING`, `OCCUPIED_TAKEOFF`, or `CLEARING`. A completed operation enters one clearing tick before another aircraft can be dispatched.

Landing service lasts three simulation ticks; takeoff lasts two. Runway utilization counts those service ticks and excludes the clearing tick. A newly submitted emergency can affect the next dispatch but cannot preempt a flight already on the runway.

## Eligibility and queue rebuilding

Flights become eligible when their scheduled time is reached, and record their queue entry time. Eligible statuses are `Queued`, `Approaching`, and `Ready`. The dispatcher constructs a fresh `std::priority_queue<int>` from those flights whenever the runway is free. It calls the comparator against current state, so queue age, fuel, and emergency escalation are recalculated before every dispatch instead of being stored as stale heap keys.

The comparator uses a lower numeric rank as higher priority:

| Rank | Eligible aircraft | Within-rank ordering |
| ---: | --- | --- |
| 0 | Emergency arrival with severity 3 or higher | Queue entry time, then flight ID |
| 1 | Other emergency arrivals; normal flights aged into this tier | For two emergency arrivals, lower `fuel / burn rate` first; otherwise queue entry time, then ID |
| 2 | Emergency departures; normal flights aged into this tier | Emergency departures use severity descending; otherwise queue entry time, then ID |
| 3 | Normal traffic before it ages | Queue entry time, then ID |

Normal-flight rank is `max(1, 3 - floor(waitMinutes / 12))`: ranks change from 3 to 2 after 12 minutes and to 1 after 24 minutes. Thus normal flights eventually move ahead of emergency departures, preventing indefinite starvation. Severity-3 emergency arrivals remain rank 0. Identical queue-entry times are resolved by stable flight ID.

For two same-rank emergency arrivals, predicted fuel endurance is `fuel / burnRate`; lower endurance is more urgent. If endurance ties, earlier queue entry and then ID decide. Emergency departure ties use severity, then queue entry and ID.

## Fuel and emergency behavior

Fuel decreases by the flight's configured burn rate per simulation tick while queued/approaching/ready and while using the runway. Every subtraction is clamped to zero. A waiting flight at 15 fuel points or lower is marked emergency with severity 2 (if it was not already an emergency), and a `fuel_critical` event is recorded. When fuel reaches zero before runway service, the flight is marked diverted and a `flight_diverted` event is recorded; it leaves the dispatch queue. Fuel reaching the threshold during runway service is logged, but does not interrupt or teleport the aircraft off the runway.

Emergency status is represented by the flight's emergency flag and severity. The API, UI, event stream, queue order, and emergency-handled statistic all use the engine state.

## Built-in scenarios and deterministic generation

Scenario presets use a seeded `std::mt19937` engine. Identical preset seed and configuration reproduce the same flight attributes. Alternating arrival/departure operations create a 50/50 preset mix.

| Scenario ID | Seed | Flights | Scheduling and emergencies |
| --- | ---: | ---: | --- |
| `normal` | 731 | 14 | 3-minute spacing after the first flight; random emergency chance 1/16 |
| `heavy` | 1942 | 30 | 2-minute spacing; random emergency chance 1/8 |
| `overload` | 5813 | 24 | Seven initial emergency flights; first five scheduled at minute 0, three at severity 3 |

Normal and heavy fuel starts from 70 through 99 points. Overload fuel starts from 35 through 79. Emergency severity and burn rates are generated by the preset RNG. Random user-configured generation has a separate seeded engine and respects the configured arrival share, fuel range, emergency percentage, and tick interval.

Scenario comparison disables automatic generation during each comparison, initializes each preset, runs exactly 180 ticks, captures statistics, and restores the live state. Therefore the comparisons use an equivalent deterministic horizon and do not advance or replace the active simulation.

## Statistics and denominators

All averages return zero when their denominator is zero.

- **Average waiting time:** completed-flight queue waits summed and divided by completed flights. A flight's queue wait is `max(0, serviceStart - queueEntered)`.
- **Average arrival delay:** for completed arrivals only, sum `max(0, serviceStart - scheduledTime)` and divide by completed arrivals.
- **Average departure delay:** same formula and denominator for completed departures.
- **Average service delay:** currently an alias of average queue waiting time, using completed flights as the denominator.
- **Completed flights:** flights whose landing/takeoff service completed.
- **Current queue length:** eligible queued, approaching, and ready flights. Scheduled, active, completed, and diverted flights are excluded.
- **Maximum queue length:** maximum eligible queue count sampled after dispatch in each tick.
- **Runway utilization:** `100 * runwayServiceTicks / elapsedSimulationTicks`; clearing ticks are excluded.
- **Emergency flights handled:** completed flights whose emergency flag is set.
- **Diversions:** flights marked diverted after fuel endurance is exhausted before runway service.
- **Maximum wait:** maximum accrued or completed wait across flights. For an active flight it ends at service start; for a waiting flight it is measured through current simulation time.

The UI charts and counters use these API values. The map interpolation uses current backend simulation time, service start, and service duration and only animates flights in an active service state.
